## 功能说明

该命令用于帮助用户理解代码、系统设计或技术问题。

解释来源包括：

- 本地代码（通过 grep / glob 搜索代码库）
- doc/ 目录中的说明文档
- 已有注释
- 网络搜索（通过 websearch / webfetch 获取外部信息）
- 必要的知识补全（knowledge-augment）

## 行为规则

执行流程：

0. 读取以下 planning 文档（如存在），作为分析背景：
   - `planning/plan.md`（项目目标、变更类型与计划图）
   - `planning/specs.md`（当前规格与实现状态）
   如文件不存在则跳过，不影响后续流程
1. 向用户询问需要解释的内容
2. 分析问题类型（代码 / 架构 / 概念）
3. 按需收集信息：
   - 本地代码：用 `grep` / `glob` 搜索代码库
   - 外部信息：用 `websearch` 搜索，必要时用 `webfetch` 抓取页面
   - knowledge-augment（知识补全）
4. 整合信息并生成解释

## 输入格式

本命令通过对话交互收集信息。Agent 应主动询问并收集：

- 需要解释的内容（代码 / 架构 / 概念）
- 期望的解释深度（快速了解 / 详细分析）

## 输出

命令执行后基于本地代码、文档与网络信息整合解释内容。

### Markdown 预览

```md
## 问题理解
...

## 解释
...

## 相关代码
...

## 补充说明
...
```

## 约束

- 优先使用本地代码与文档
- 不允许仅依赖网络信息
- 解释必须与项目上下文相关
- 避免长篇无关理论
