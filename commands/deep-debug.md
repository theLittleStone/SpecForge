## 功能说明

该命令用于在验收或调试阶段，协助用户定位和分析 bug。

支持：

- 错误定位
- 原因分析
- 修复建议
- 验证路径设计

## 行为规则

执行流程：

0. 读取以下 planning 文档（如存在），作为分析背景：
   - `planning/requirement.md`（项目目标与变更类型）
   - `planning/architecture.md`（变更影响与设计决策）
   - `planning/specifications.md`（当前规格与实现状态）
   如文件不存在则跳过，不影响后续流程
1. 询问用户 bug 描述
2. 收集信息：
   - 报错信息
   - 相关代码
   - 测试情况
3. 建立问题模型
4. 分析可能原因
5. 逐步验证假设
6. 输出修复建议与验证方案

必要时调用：

- 用 `grep` / `glob` 搜索代码库定位代码
- 用 `websearch` 联网查找相关资料
- knowledge-augment（机制解释）

## 输入格式

本命令通过对话交互收集信息。Agent 应主动询问并收集：
- 问题描述（发生了什么）
- 错误日志或控制台输出
- 相关代码文件路径
- 可否复现、复现步骤

## 输出

命令执行后基于收集的信息与假设验证，输出结构化分析报告。

### Markdown 预览

```md
## 问题分析
...

## 可能原因
- 原因1
- 原因2

## 验证步骤
...

## 修复建议
...

## 风险提示
...
```


## 调试策略

- 优先基于 planning 文档（requirement / architecture / specifications）分析目标与规格一致性
- 检查实现是否符合定义
- 检查测试是否覆盖异常路径
- 避免直接修改代码，先验证假设

## 约束

- 不允许跳过分析直接给结论
- 必须提供验证步骤
- 优先最小修改原则
